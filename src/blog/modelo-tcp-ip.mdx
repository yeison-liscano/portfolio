Palabras clave: modelo TCP/IP, capas, encapsulación, aplicación, transporte,
internet, enlace

Cuando abres una página web, tu computador le envía un mensaje corto a un
servidor. Ese mensaje cruza varias redes y llega intacto. El modelo TCP/IP
explica cómo lo logra: reparte el trabajo en cuatro capas, y cada capa resuelve
un solo problema. Entenderlo tiene un uso práctico. Cuando una conexión falla,
el mensaje de error dice qué capa falló, y eso te dice dónde buscar. Este post
explica las cuatro capas con un solo ejemplo, una petición web, y termina con
una tabla para leer los errores de conexión más comunes.

## Enviar un mensaje por Internet se parece a enviar una carta

Para que una carta llegue hacen falta cuatro cosas:

1. El texto de la carta.
2. El nombre de la persona que la recibe.
3. La dirección de la casa.
4. El camión o la moto que la lleva en cada tramo del camino.

Tú solo escribes el texto y el nombre. El correo se encarga del resto, y tú no
necesitas saber qué camiones usó. TCP/IP reparte el trabajo de la misma forma.
¿Quién hace cada parte cuando el mensaje es una petición web? La respuesta está
más abajo.

## Cada capa responde una sola pregunta

El modelo TCP/IP tiene cuatro capas. Cada una responde una pregunta distinta:

| Capa       | Pregunta                         | En la carta         | En una petición web                    |
| ---------- | -------------------------------- | ------------------- | -------------------------------------- |
| Aplicación | ¿Qué quiero decir?               | el texto            | `GET /`, en HTTP                       |
| Transporte | ¿Qué programa lo recibe?         | el nombre           | el puerto 80, con TCP                  |
| Internet   | ¿Qué computador lo recibe?       | la dirección        | `10.0.2.30`, con IP                    |
| Enlace     | ¿Cómo llega al siguiente equipo? | el camión del tramo | la MAC del router, con Ethernet o WiFi |

En palabras simples:

- **Aplicación.** Es el idioma entre dos programas. Un navegador y un servidor
  web hablan HTTP.
- **Transporte.** Un computador ejecuta muchos programas a la vez, y el puerto
  dice a cuál va el mensaje. TCP, además, revisa que todo llegue completo y en
  orden, y vuelve a enviar lo que se pierde.
- **Internet.** La dirección IP identifica un computador en cualquier red. Los
  routers la leen para decidir por dónde sigue el mensaje.
- **Enlace.** Lleva el mensaje solo hasta el siguiente equipo, por ejemplo del
  portátil al router de la casa. Usa otra dirección, la MAC, que solo sirve
  dentro de una misma red local.

## Cada capa envuelve el mensaje de la capa de arriba

Tomemos una petición real. El comando `curl http://10.0.2.30/` le pide la página
principal a un servidor. Este es el texto que envía:

```text
GET / HTTP/1.1
Host: 10.0.2.30
User-Agent: curl/8.5.0
Accept: */*
```

Con los saltos de línea y la línea vacía del final, son 72 bytes. Antes de
salir, cada capa le pone delante su propia cabecera, como un sobre dentro de
otro sobre. TCP agrega 32 bytes con los puertos. IP agrega 20 con las
direcciones de origen y destino. Ethernet agrega 14 con las direcciones MAC, y 4
más al final para detectar errores. Esto se llama **encapsulación**.

Medí estos tamaños en un laboratorio de Linux con `tcpdump`, una herramienta que
captura lo que pasa por la tarjeta de red. La trama capturada midió 138 bytes,
más los 4 que la tarjeta agrega al final. Al llegar, el servidor hace lo
contrario. Cada capa quita su sobre y le pasa el resto a la capa de arriba,
hasta que el servidor web lee los mismos 72 bytes.

## Tu programa solo escribe la capa de aplicación

Esto responde la pregunta de la carta. curl solo escribió los 72 bytes de la
petición. No escribió puertos, direcciones IP ni direcciones MAC. El sistema
operativo agregó las cabeceras de TCP e IP, y la tarjeta de red armó la trama
Ethernet.

Por eso un programador puede usar la red sin conocer sus detalles. Solo dice a
dónde va el mensaje, con una dirección y un puerto, y qué dice. Si mañana el
computador cambia de WiFi a cable, el programa no cambia.

## TCP/IP junta en una capa lo que el modelo OSI separa en tres

Existe otro modelo de capas muy conocido, el modelo OSI, con siete capas. TCP/IP
es más simple en dos puntos:

- Junta aplicación, presentación y sesión en una sola capa de aplicación.
- Junta enlace y física en una sola capa de enlace.

## Cuando una conexión falla, el error dice qué capa falló

Como cada capa tiene un solo trabajo, cada una falla de una forma distinta. Este
programa en Python intenta conectarse a tres destinos:

```python
import socket


def probar(host, puerto):
    try:
        socket.create_connection((host, puerto), timeout=3).close()
        print("conectado")
    except OSError as error:
        print(type(error).__name__, "-", error)


probar("servidor.invalid", 80)  # un nombre que no existe
probar("127.0.0.1", 81)  # mi computador, un puerto sin programa
probar("10.9.9.9", 80)  # una red sin ruta desde este equipo
```

Esta es la salida en un Linux sin ruta hacia `10.9.9.9`:

```text
gaierror - [Errno -2] Name or service not known
ConnectionRefusedError - [Errno 111] Connection refused
OSError - [Errno 101] Network is unreachable
```

Cada error apunta a una capa:

| Error                       | Capa que falló   | Qué significa                                                       |
| --------------------------- | ---------------- | ------------------------------------------------------------------- |
| `Name or service not known` | aplicación (DNS) | el nombre no existe, así que nunca se obtuvo una dirección IP       |
| `Connection refused`        | transporte       | el computador respondió, pero ningún programa escucha en ese puerto |
| `Network is unreachable`    | internet         | no hay una ruta hacia esa red                                       |

`Connection refused` es una buena noticia a medias. Dice que la red funciona
hasta el servidor, y que el problema está en el servidor: el programa no está
corriendo o escucha en otro puerto. Hay un cuarto caso, que este ejemplo no
muestra. Si nadie responde, la conexión espera y termina con un `TimeoutError`.
Eso suele significar que un firewall descarta los paquetes o que el equipo está
apagado.

## Cuatro capas, cuatro preguntas, y tu programa solo responde una

El modelo TCP/IP reparte el envío de un mensaje en cuatro preguntas: qué dices,
a qué programa, a qué computador y cómo llegar al siguiente equipo. Cada capa
responde una y envuelve el mensaje de la capa de arriba. Tu programa solo
responde la primera. El sistema operativo y la tarjeta de red responden las
otras tres.

La idea para llevarse es esta: cuando una conexión falle, lee el error y busca a
qué capa pertenece. Ahí es donde empiezas a buscar.
