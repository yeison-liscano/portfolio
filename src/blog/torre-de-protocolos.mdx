Palabras clave: torre de protocolos, capas, entidades pares, encapsulación,
repetidor, switch, router, WiFi, PPP, Ethernet

Tu portátil se conecta por WiFi. El servidor de una página web se conecta por
cable. Entre los dos hay routers unidos por otros tipos de enlace. Los dos
extremos no usan la misma tecnología de red, y aun así se entienden. ¿Cómo? La
respuesta es la torre de protocolos: la lista de protocolos que usa cada equipo,
ordenada por capas. Este post la explica con un ejemplo de cuatro equipos.
También muestra qué puede leer cada tipo de equipo. Al final queda una regla
útil para la seguridad de una red.

## Una torre de protocolos es la lista de protocolos de un equipo, por capas

Cada equipo de una red ejecuta varios protocolos a la vez, uno por capa. Si los
escribes uno encima de otro, del más cercano al usuario al más cercano al cable,
obtienes su torre de protocolos.

Esta es la torre de un portátil que abre una página web en Chrome, conectado por
WiFi:

| Capa       | Protocolo | Para qué sirve                                 |
| ---------- | --------- | ---------------------------------------------- |
| Aplicación | HTTP      | el idioma entre el navegador y el servidor web |
| Transporte | TCP       | entregar los datos completos y en orden        |
| Red        | IP        | llevar los datos de una red a otra             |
| Enlace     | 802.11    | el estándar de WiFi                            |
| Física     | 802.11ax  | cómo viajan los bits por radio (Wi-Fi 6)       |

## No todos los equipos llegan hasta la capa de arriba

Para enviar, un equipo envuelve los datos capa por capa, de arriba hacia abajo.
Para recibir, los desenvuelve de abajo hacia arriba. Pero no todos los equipos
desenvuelven hasta el final. Cada tipo de equipo llega hasta una capa, y lo que
va por encima de esa capa no lo lee.

- **Repetidor (hub).** Llega a la capa física. Lo que entra por un puerto lo
  copia en los demás, como ceros y unos. No lee nada.
- **Switch.** Llega a la capa de enlace. Lee la dirección MAC de destino y envía
  los datos solo por el puerto donde está ese equipo. Conecta equipos dentro de
  una misma red.
- **Router.** Llega a la capa de red. Lee la dirección IP de destino y decide a
  qué red enviar los datos. Conecta redes distintas.
- **Sistema final.** Tu portátil o un servidor. Tiene todas las capas, porque
  ahí corren los programas que envían y reciben los datos.

## En el ejemplo, cada router cambia el enlace y deja igual lo de arriba

El ejemplo tiene cuatro equipos. Un portátil con Chrome se conecta por WiFi al
router 1. El router 1 se conecta al router 2 por un enlace punto a punto, un
cable directo entre los dos, que usa el protocolo PPP. El router 2 se conecta
por Ethernet a un servidor que ejecuta Apache, un servidor web.

Las torres de la figura son estas:

- **Portátil:** HTTP, TCP, IP, 802.11 y 802.11ax.
- **Router 1:** del lado del portátil, IP, 802.11 y 802.11ax. Del lado del
  router 2, IP, PPP y la capa física de ese cable.
- **Router 2:** del lado del router 1, IP, PPP y la misma capa física. Del lado
  del servidor, IP, 802.3 y 802.3ab. 802.3 es el estándar de Ethernet, y 802.3ab
  es Ethernet a 1 Gb/s por cable de cobre.
- **Servidor:** HTTP, TCP, IP, 802.3 y 802.3ab.

## Cada capa solo habla con la misma capa del otro equipo

La parte de un equipo que ejecuta un protocolo se llama **entidad**. En el
portátil, la entidad de aplicación es Chrome. Dos entidades de la misma capa, en
equipos distintos, se llaman **entidades pares**. Las entidades pares hablan el
mismo protocolo y solo se entienden entre ellas.

En el ejemplo, los pares son estos:

| Capa            | Entidades pares                     | Protocolo                       |
| --------------- | ----------------------------------- | ------------------------------- |
| Aplicación      | Chrome y Apache                     | HTTP                            |
| Transporte      | el portátil y el servidor           | TCP                             |
| Red             | los cuatro equipos                  | IP                              |
| Enlace y física | solo los dos equipos de cada enlace | WiFi, luego PPP, luego Ethernet |

Esto responde la pregunta del principio. El portátil nunca habla WiFi con el
servidor. Habla WiFi con el router 1, y ahí termina el WiFi. Lo que todos los
equipos comparten es IP, y lo que comparten los dos extremos es TCP y HTTP. Las
capas de abajo cambian en cada tramo, y las de arriba no se enteran.

Pasa lo mismo con un paquete que envías por correo. Puede viajar en moto, luego
en avión y luego en camión. La dirección escrita en la caja no cambia, y el
contenido llega igual.

## Para saber qué puede hacer un equipo, mira hasta qué capa llega

Dos equipos se entienden sin usar la misma red porque comparten las capas de
arriba. Las capas de enlace y física pueden cambiar en cada tramo, porque solo
las usan los dos equipos de ese tramo. Cada router saca los datos de una trama y
los mete en otra, sin tocar lo que va adentro.

La idea para llevarse sirve para la seguridad: un equipo solo puede revisar lo
que su capa le deja leer.

- Un switch ve direcciones MAC, pero no direcciones IP. Por sí solo, no puede
  bloquear una dirección IP.
- Un router o un firewall de red ve direcciones IP y puertos, pero no qué página
  pides.
- Solo un equipo que llega a la capa de aplicación, como un proxy, puede decidir
  según la página. Si la conexión usa HTTPS, además necesita descifrarla.

Antes de confiar en un control de seguridad, pregunta hasta qué capa llega el
equipo que lo aplica.
